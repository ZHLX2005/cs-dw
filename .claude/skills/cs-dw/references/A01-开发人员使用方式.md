# A01 — 开发人员使用方式

> 本 ref 仅适用于 cs-dw（本地根目录 `D:\a_js\js_proj\nx-drawer`）。
> 相关：模块职责见 [[A02-模块职责边界]]，扩展步骤见 [[A03-扩展指南]]。

## 1. 环境要求

| 工具 | 用途 | 必需 |
| --- | --- | --- |
| .NET 8 SDK | 编译 WPF（`net8.0-windows`） | ✅ 必需 |
| Node.js | 跑 `tools/gen-logos.mjs` 重新生成 logo | ❌ 仅改 logo 时 |
| Visual Studio | —— | ❌ 不需要，`dotnet` CLI 足够 |

**没有 NuGet 依赖**，不需要 `dotnet restore` 拉包，也不会遇到 NuGet 源问题。

> ⚠️ 若 `dotnet build` 报 `无法找到回退包文件夹`，说明机器级 NuGet 配置指向了已不存在的盘符
> （VS 安装时写的 `Microsoft.VisualStudio.FallbackLocation.config`）。
> 修法：用户级 `%APPDATA%\NuGet\NuGet.Config` 加 `<fallbackPackageFolders><clear /></fallbackPackageFolders>`。

## 2. 构建与运行

```bash
cd D:\a_js\js_proj\nx-drawer\src

dotnet build -c Release              # 构建（零警告是基线）
dotnet run -c Release                # 常驻运行
```

产物：`src/bin/Release/net8.0-windows/nx-drawer.exe`

**旧实例会锁住 exe 导致构建失败**（`MSB3027 ... 文件被 nx-drawer (pid) 锁定`）：

```bash
cmd //c "taskkill /IM nx-drawer.exe /F"
```

> Git Bash 里 `taskkill /PID x` 会被当成路径，必须走 `cmd //c`。

## 3. 自测模式（**不要靠肉眼验证**）

本项目每个易错行为都有对应的程序化自测。改完代码跑对应模式，看输出里的断言行。

| 模式 | 验证什么 | 判据 |
| --- | --- | --- |
| `--smoke` | 窗口能起来、能正常退出 | exit=0 |
| `--probe` | 显隐位置真的在动 | 输出 `-336 → 0 → -336`，且 `HitTest` 同步翻转 |
| `--launch-test` | 启动链路（启动→退出回调→计数刷新）不崩 | 打印 `[result] 启动链路正常…`，exit=0 |
| `--edge-test` | 边缘悬浮唤醒真的生效 | 输出 `Revealed=False → True` |

```bash
cd src
dotnet run -c Release -- --launch-test
dotnet run -c Release -- --edge-test
```

四个模式都在 `src/App.xaml.cs` 的 `OnStartup` 里按 `e.Args` 分派。

## 4. 配置文件 `drawer.json`

位置优先级：**exe 同目录 → 当前工作目录**（`ConfigStore.Locate()`）。都不存在时写出默认模板。

```jsonc
{
  "edge": "left",        // left | top | right —— 停靠边
  "width": 340,          // 抽屉宽（DIP）
  "height": 0,           // 高（DIP），0 = 工作区高度的 80%
  "opacity": 0.92,       // 整体不透明度 0.3~1.0
  "revealDelayMs": 120,  // 悬停多久滑出（防误触）
  "hideDelayMs": 600,    // 离开多久收回
  "slideMs": 220,        // 动画时长
  "apps": [
    { "name": "nx-kv", "logo": "assets/logos/nx-kv/logo-rounded.png", "cmd": "nx-kv serve", "group": "nx 系列" },
    { "name": "GitHub", "url": "https://github.com", "group": "常用" }
  ]
}
```

| 字段 | 语义 |
| --- | --- |
| `cmd` | 经 `cmd /c` 执行，支持 PATH 里的 `nx-xxx` shim（含 `.cmd`） |
| `url` | 交给系统默认浏览器，不进子进程管理 |
| `group` | 相同 group 归为同一分区并**共享运行计数**；留空则用 `name` |
| `logo` | 相对 exe 目录的路径。缺省或加载失败 → 回退到首字母色块占位 |
| `cwd` | 工作目录，留空继承抽屉进程 |

## 5. 交互约定

| 操作 | 行为 |
| --- | --- |
| 鼠标贴边缘悬停 `revealDelayMs` | 抽屉滑出（隐藏态只露 4DIP 把手） |
| 鼠标移开 `hideDelayMs` | 抽屉收回 |
| `Ctrl+Alt+D` | 全局热键切换显隐（被占用时静默降级，边缘呼出不受影响） |
| 托盘左键 | 切换显隐 |
| 托盘右键 | 菜单：显示/隐藏 · 设置… · 退出 |
| 左键卡片 | 启动（可多实例，徽标 `●N`） |
| 右键卡片 / `■` | `taskkill /T /F` 杀整棵进程树（shim → node → 子命令） |
| 搜索框输入 | 实时过滤（匹配 name / cmd / url / group） |
| `↑` `↓` `Enter` | 键盘选卡并启动；`Esc` 收起 |

## 6. 设置页

托盘右键 →「设置…」。编辑停靠边 / 宽高 / 透明度 / 延迟 / 动画 / 应用列表，保存写回 `drawer.json`
并热重载（`EdgeWatcher.ApplyConfig`）。

**应用列表用纯文本格式**，每行一条：

```
名称 | 命令或网址 | 分组
```

- `http://` / `https://` 开头自动识别为网址（走浏览器），否则当命令
- 分组留空则该应用自成一分区
- **logo 路径不在编辑面内**——保存时按名称从旧配置继承（`ConfigStore.Save` 的 `previous` 参数）。
  改 `ConfigStore.Save` 时别破坏这个继承，否则用户保存一次图标全丢。

## 7. CI 与发版

### CI（`.github/workflows/ci.yml`）

触发：`push` 到 main/master、`pull_request`、手动。Runner 必须是 `windows-latest`（WPF 是 Windows-only）。

步骤：Checkout → Setup .NET 8 → Restore → Build → **3 个自测** → Upload artifact。

> **自测进 CI 是硬要求**：新增可验证行为时，同步在 `src/App.xaml.cs` 加自测模式并挂进 `ci.yml`。

### 发版（`.github/workflows/release.yml`）

触发：推 `v*` tag，或手动填 tag。

```bash
git tag -a v0.1.1 -m "Release v0.1.1"
git push origin v0.1.1
```

产出 `cs-dw-<version>-win-x64.zip` + 自动生成的 release notes。

> ⚠️ **windows runner 的默认 shell 是 PowerShell，不是 bash**。
> workflow 里写 `if/then/fi` 会直接 ParserError——显式 `shell: pwsh` 并用 pwsh 语法。
> 另：注释里写 `${{ }}` 会被 YAML 当表达式解析，**actionlint 会报错**。
>
> 校验：`actionlint .github/workflows/*.yml` 必须 exit=0。

### 产物内容

`dotnet publish -c Release -o publish -r win-x64 --self-contained false` →
`nx-drawer.exe` / `.dll` / `.deps.json` / `.runtimeconfig.json` / `drawer.json` / `assets/`。

`drawer.json` 由 csproj 的 `<None Include="drawer.json" CopyToOutputDirectory="PreserveNewest" />` 随包发布，
用户解压即可改。

## 8. Logo 重新生成

```bash
cd D:\a_js\js_proj\nx-drawer
node tools/gen-logos.mjs
```

复用 `../nx-pg/tools/logo-gen`（零依赖，撞色方案表与其一致）。产物按应用分目录：

```
src/assets/logos/<name>/logo-rounded.png   ← 卡片主图（配置里引用的就是它）
src/assets/logos/<name>/favicon-16|32|48.png
src/assets/logos/<name>/favicon.ico
src/assets/app.ico                        ← 程序/托盘图标
```

> 改了 `tools/gen-logos.mjs` 的目录布局，**必须同步改 `src/drawer.json` 里的 logo 路径**，
> 否则图标全丢（回退到首字母色块）。

## 9. 提交前检查

```bash
cd src
dotnet build -c Release                                    # 零警告
dotnet run -c Release -- --launch-test                    # 启动链路
dotnet run -c Release -- --edge-test                       # 边缘唤醒
actionlint ../.github/workflows/*.yml                      # exit=0
```

然后确认 `git status` 干净再推送——CI 用的是推送时的内容。
