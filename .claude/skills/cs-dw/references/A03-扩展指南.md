# A03 — 扩展指南

> 本 ref 仅适用于 cs-dw（本地根目录 `D:\a_js\js_proj\nx-drawer`）。
> 相关：模块职责见 [[A02-模块职责边界]]，构建与自测命令见 [[A01-开发人员使用方式]]。

每个扩展都遵循同一条节奏：**改代码 → 加自测 → 挂进 CI → 提交**。

## 1. 加一个新的应用卡片（最常见）

**通常什么都不用做**——`drawer.json` 的 `apps` 数组就是全部。编辑配置即可：

```jsonc
{ "name": "nx-rp", "logo": "assets/logos/nx-rp/logo-rounded.png", "cmd": "nx-rp", "group": "nx 系列" }
```

| 想要 | 怎么配 |
| --- | --- |
| 启动 CLI | `"cmd": "nx-rp serve --port 8080"` |
| 打开网址 | `"url": "https://example.com"` |
| 单独分区 | 不填 `group`（则自成一分区） |
| 归入某分区 | `"group": "nx 系列"` |
| 不显示图标 | 不填 `logo`（回退首字母色块） |

### 加一个**新 logo**

```bash
cd D:\a_js\js_proj\nx-drawer
node tools/gen-logos.mjs     # 重新生成全部
```

要加新应用，在 `tools/gen-logos.mjs` 的 `APPS` 数组里加一项：

```js
const APPS = [
  ['nx-kv', 'vandyke'], ['nx-nx', 'mars'],    // ['名字', '撞色方案']
  ...
  ['nx-xx', 'klein'],
];
```

撞色方案见 `../nx-pg/tools/logo-gen/index.mjs` 的 `SCHEMES`：
`klein`(克莱因蓝) `mars`(马尔斯绿) `hermes`(爱马仕橙) `tiffany`(蒂芙尼蓝)
`red`(中国红) `vandyke`(凡戴克棕) `prussian`(普鲁士蓝)。

生成后在 `src/drawer.json` 里引用：`"logo": "assets/logos/nx-xx/logo-rounded.png"`。

## 2. 加一个新的配置项

四步，缺一不可：

### ① 模型加属性（`src/Config.cs`）

```csharp
public sealed class DrawerConfig
{
    /// <summary>xxx 的说明</summary>
    [JsonPropertyName("xxx")]
    public int Xxx { get; set; } = 默认值;
}
```

### ② 消费方读它

- 几何类 → `EdgeWatcher`（注意 `ShownPos`/`HiddenPos` 都要算）
- 外观类 → `MainWindow` 构造里应用到控件

### ③ 设置页暴露它（`src/SettingsWindow.xaml` + `.xaml.cs`）

```xml
<TextBlock Text="说明" Foreground="#B4FFFFFF" FontSize="12" Margin="0,0,0,6"/>
<TextBox x:Name="XxxBox" Background="#1FFFFFFF" Foreground="#F5F5F7"
         BorderBrush="#28FFFFFF" CaretBrush="#FFE76F" Padding="8,6" Text="默认值"/>
```

```csharp
// 读回
_cfg.Xxx = (int)ParseNum(XxxBox.Text, 默认值);
// 保存（记得把旧配置传进去，继承 logo 等未暴露字段）
ConfigStore.Save(_path, _cfg, _previous);
```

### ④ 保存后热重载（`src/MainWindow.xaml.cs`）

```csharp
if (win.ShowDialog() == true)
{
    _watcher.ApplyConfig(_cfg);   // 几何变了要重新落位
    // 外观变了直接应用
    DrawerPanel.Opacity = _cfg.Opacity;
    EdgeBadge.Text = _cfg.Edge;
    UpdateStatus();
}
```

> ⚠️ `ConfigStore.Save` 的第三个参数 `previous` **不能省**——它负责把设置页没暴露的
> 字段（`logo` / `cwd`）按名称从旧配置继承。省了会导致用户保存一次图标全丢。

## 3. 加一个新的自测模式

自测是本项目的**质量闸门**——历史上多个"看起来能跑但其实没生效"的 bug，都是靠自测发现的
（`--edge-test` 就直接抓出过"轮询从未启动"）。

### ① 在 `src/App.xaml.cs` 的 `OnStartup` 分派

```csharp
if (e.Args.Contains("--my-test"))
{
    var t = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(400) };
    var n = 0;
    var ok = true;
    t.Tick += (_, _) =>
    {
        n++;
        if (n == 1) win.DoMyTest();
        var running = win.SomeState;
        if (running > 0) sawRunning = true;
        Console.WriteLine($"[{n * 400,5}ms] Running={running}");
        if (n >= 8)
        {
            t.Stop();
            ok = /* 你的断言 */;
            Console.WriteLine(ok ? "[result] 通过" : "[result] 失败");
            win.Close();
            Shutdown(ok ? 0 : 1);   // ← 必须用退出码表达成败
        }
    };
    t.Start();
}
```

### ② 暴露必要的状态给自测读（`src/MainWindow.xaml.cs`）

```csharp
public int SomeState => _procs.Counts.Values.Sum();
public void DoMyTest() { /* 触发被测行为 */ }
```

### ③ 挂进 CI（`.github/workflows/ci.yml`）

```yaml
      - name: My test
        run: dotnet run --project src/NxDrawer.csproj -c Release --no-build -- --my-test
```

**退出码非 0 即 CI 红**——这样 CI 才能真正拦住回归。

### 自测模式的硬性要求

| 要求 | 理由 |
| --- | --- |
| 必须有**断言**并用退出码表达 | 没有断言的自测等于摆设，坏了也不报警 |
| 不能依赖肉眼 | 位置/状态都从代码读出来打印 |
| 不能依赖真实外部环境 | 用 `cmd /c exit 0` 这类可控命令，别真启 nx 服务 |
| 结束前要 `Shutdown(0/1)` | 否则 CI 挂死 |

## 4. 加一种新的交互（按钮 / 菜单项 / 快捷键）

### 托盘菜单项

`src/TrayIcon.cs`：

```csharp
private const int CMD_MY_ACTION = 1004;

// ShowContextMenu 里
AppendMenu(hMenu, MF_STRING, CMD_MY_ACTION, "我的操作");

// 回调分发里
else if (cmd == CMD_MY_ACTION) MyActionRequested?.Invoke();
```

再在 `TrayIcon` 声明 `public event Action? MyActionRequested;`，
最后在 `src/MainWindow.xaml.cs` 订阅：

```csharp
_tray.MyActionRequested += () => Dispatcher.Invoke(DoMyAction);
```

> 菜单分隔线要用 `MF_SEPARATOR`（0x0800），不是 `MF_STRING` 传 null。

### 全局快捷键

`src/GlobalHotkey` 目前固定 `Ctrl+Alt+D`（`MainWindow` 构造里注册）。要加第二个热键：

```csharp
// GlobalHotkey 内部：把 HOTKEY_ID 改成数组，支持多键
```

> 注意：`RegisterHotKey` 失败（被别的程序占用）会**静默降级**——不报错但热键不可用。
> 换热键时先确认目标组合没被占用。

### 抽屉内的交互

在 `src/MainWindow.xaml` 加控件，在 `MainWindow.xaml.cs` 挂事件。
**所有 UI 事件天然在 UI 线程**，不需要 `Dispatcher.Invoke`。

## 5. 加一种新的卡片行为（比如"以管理员启动"）

`src/ProcessManager.cs` 的 `Start` 里改 `ProcessStartInfo`：

```csharp
var psi = new ProcessStartInfo
{
    FileName = "cmd.exe",
    Arguments = $"/c {app.Cmd}",
    UseShellExecute = false,
    CreateNoWindow = true,
    WorkingDirectory = ...,
    // 需要提权时：
    // Verb = "runas",
};
```

提权会弹 UAC，`UseShellExecute` 必须为 `true`，但那样 `CreateNoWindow` 无效——
两者互斥，**不要同时设**。

## 6. 扩展时的检查清单

- [ ] 改了 `Config` 模型 → 设置页也要能编辑它，且 `ConfigStore.Save` 传了 `previous`
- [ ] 改了 logo 目录布局 → `src/drawer.json` 的路径同步改了
- [ ] 新增了事件 → 确认触发线程；非 UI 线程的**订阅处必须 `Dispatcher.Invoke`**
- [ ] 新增了可验证行为 → 加了自测模式 + 挂进 `ci.yml` + 用退出码表达成败
- [ ] 改了 workflow → `actionlint .github/workflows/*.yml` exit=0
- [ ] `dotnet build -c Release` 零警告
- [ ] 三个既有自测仍通过：`--launch-test` / `--edge-test` / `--smoke`
- [ ] 改了 `src/drawer.json` 模板 → 记得它随包发布（csproj 的 `<None Include="drawer.json" ...>`）

## 7. 不要做的事

| 别做 | 为什么 |
| --- | --- |
| 引入 NuGet 包（HandyControl / WinUIEx 等） | 本项目刻意保持零依赖；加包前先确认 Win32 手写不更麻烦 |
| 在 `ProcessManager` / `EdgeWatcher` / `TrayIcon` 里碰 UI | 破坏线程边界，参见 A02 |
| 用 `RenderTransform` 做显隐 | 不影响命中测试 |
| 用 `SystemParameters.WorkArea` 判热区 | 只给主屏 |
| 只靠肉眼验证交互 | 必须写自测 |
| 提交前不跑 actionlint | YAML 里的 `${{ }}` 注释会引发解析错误 |
